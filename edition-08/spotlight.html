// toque repetido em rajada? descarta com segurança
const MIN_INTERVALO = 800 // ms

async function salvarResposta(resposta) {
  const agora = Date.now()

  // guard 1 — tempo: ignora rajadas
  if (agora - ultimaResposta < MIN_INTERVALO) return

  // guard 2 — conteúdo: dedup por pergunta + hash
  if (await jaRespondida(resposta)) return

  ultimaResposta = agora
  await persistir(resposta) // 1 toque = 1 resposta
}
Por que isso importa
1. Campo real = rede lenta + usuário insistindo: toda ação repetível precisa de guard de tempo + dedup por conteúdo (#13108).
2. Regressão de performance se pega medindo: no #13175 o vilão era re-render em cascata do formulário — profile antes de otimizar.
3. Guard barato no cliente evita limpeza cara no banco: as ~233 respostas pendentes do #13212 mostram o custo de não ter.
4. Padrão reaproveitável: a mesma receita vale para fila de envio, anexos e qualquer ação offline-first.
Regra de bolso
Se o usuário pode disparar 2× a mesma ação, um dia ele vai disparar. Debounce no tempo, dedup no conteúdo e idempotência no servidor — as três camadas juntas.
